[개발 참고 — 나중에 고칠 사람에게]
  - 단일 파일 앱: index.html 안에 HTML·CSS·JavaScript 가 모두 있어요. 빌드 과정 없음.
  - 저장소: 브라우저 IndexedDB 'avory-desk' (저장소: partners, pos, ships, txns, docs, kv, files, gone).
      pos 에는 PO와 청구서(kind:'bill')가 함께 들어가요. dir: export=받을 돈 / import=줄 돈.
      files 에는 첨부 원본(PDF·사진)이 Blob 으로 저장돼요.
      gone 은 지운 기록(합치기 때 삭제를 다른 기기에 전하기 위함).
  - 백업 형식: JSON { app:'avory-desk', format:2, company, partners, pos, ships, txns, docs, gone, files[base64] }
      불러오기 '합치기' = 항목별 updatedAt 이 더 늦은 쪽이 이김.
  - 외부 라이브러리(필요할 때만 로드, cdnjs → jsDelivr → unpkg 순서로 시도, sw.js 가 캐시):
      html2canvas 1.4.1, jsPDF 2.5.1 (PDF 저장) · SheetJS xlsx 0.18.5 (엑셀) · pdf.js 3.11.174 (PDF 읽기) · JSZip 3.10.1
  - 서류 서식: 회사 표준 서식(docAvory, 中·EN) / 기본 서식(docEn·docKo). 회사 정보·계좌·로고·도장은 앱 설정에서.
  - 글자 인식: 은행 문자·은행 앱 화면·주문서·청구서·명함은 앱 안의 규칙(parse…Text 함수들)으로 읽어요.

[2026.11.07-1 업데이트 · 글자 인식 개선]
- 우리 회사를 거래처로 잘못 넣지 않아요. 상호가 조금 다르게 적혀도(CO.,LIMITED, 艾沃瑞, 번체 電子) 사진에서 한두 글자가 잘못 읽혀도 우리 회사로 알아봐요.
  설정 → 회사 정보 '우리 회사 다른 이름 (인식용)'에 다른 이름을 적어 두면 그 이름도 우리 회사로 봐요.
  이미 거래처 목록에 우리 회사가 들어가 있으면 '확인할 일'에 알려 줘요.
- 중국어 서류에서 누가 사고 누가 파는지 읽어요: 甲方/乙方, 需方/供方, 买方/卖方, 购买方/销售方, 收款方/付款方, 客户/供应商, 致·TO.
  우리 회사가 받는 쪽(收款方)이면 받을 돈, 주는 쪽이면 줄 돈으로 정리하고, 상대 회사만 거래처로 넣어요.
- 합계 줄이 없거나 다르게 적힌 청구서도 읽어요 (本次付款申请金额, 应收金额… · 번호 붙은 품목을 더하기 · 大写 금액 贰万柒仟肆佰元整).
- 사진 읽기: 표의 한 줄(날짜와 거래 종류, 품목과 금액)을 한 줄로 읽고 칸 사이를 띄워요. 큰 제목(INVOICE, 付款通知单)도 다시 읽어요.
  은행 앱 화면은 거래 종류가 옆 줄로 밀리지 않고, 흐리게 읽힌 회사 이름은 같은 계좌번호의 거래처로 바로잡아요.
- 엑셀: '청구서·서류 올리기'에 엑셀(xlsx·xls·csv)을 넣으면 청구서·견적서·付款通知单은 서류로, 은행 거래내역은 입출금으로 읽어요.
  중국 은행 엑셀(中国银行·招商银行 등: 交易金额 +/-, 借方/贷方, 付款人/收款人, 币种, GBK 글자)과 한국 은행 엑셀 모두 돼요.
- 거래처 정보만 있는 글(명함, 위챗 开票资料·收款账户)을 붙여넣으면 '거래처로 등록' 버튼이 떠요.
